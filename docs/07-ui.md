## 1. 整体布局

mp_agent 的 TUI 界面基于 Ratatui + Crossterm 构建，采用垂直分层布局：

```
┌─────────────────────────────────────────────────────┐
│                                                     │
│  聊天区域 (ChatArea)                                 │
│  - 用户消息                                          │
│  - Assistant 回复                                    │
│  - 工具调用/结果                                     │
│  - 流式预览（正在生成时）                            │
│                                                     │
│                                                     │
│                                                     │
│                                                     │
│                                                     │
│                                                     │
├─────────────────────────────────────────────────────┤
│  建议区域 (Suggestions) — Slash 命令时显示           │
│  ▶ /help    Show help information                   │
│  ▶ /clear   Clear chat history                      │
│  ...                                                │
├─────────────────────────────────────────────────────┤
│  输入区域 (InputArea)                                │
│  > Type a message... (/help for commands) █         │
├─────────────────────────────────────────────────────┤
│  状态栏 (Status Bar)                                 │
│  mp_agent | 12 tools | Ready  ▾ Processing           │
│  或                                                  │
│  【Permission】WRITE /path/file | write_file [y]...  │
│  或                                                  │
│  【Choice】Pick an option (1-3): ...                 │
└─────────────────────────────────────────────────────┘
```

布局计算在 `app.rs::draw()` 中完成，使用 Ratatui 的 `Layout` 约束：

- 聊天区域：`Constraint::Min(5)` — 占据剩余空间，最小 5 行
- 建议区域：`Constraint::Length(N)` — 仅 slash 命令时显示，高度 = 匹配数 + 2
- 输入区域：`Constraint::Length(3)` — 固定 3 行（含边框）
- 状态栏：`Constraint::Length(1)` — 固定 1 行

## 2. ChatArea — 聊天区域

### 2.1 消息类型

`ChatMessage` 枚举定义了 6 种消息类型：

| 类型 | 渲染样式 | 说明 |
|---|---|---|
| `User(text)` | 绿色 `◆` 标记 + 白色文字 | 用户输入 |
| `Assistant(text)` | 青色 `◆` 标记 + Markdown 渲染 | AI 回复 |
| `ToolCall { name, args }` | 黄色 `⚡` 标记 + 参数摘要 | 工具调用开始 |
| `ToolResult { name, result }` | `✔` / `✗` 标记 + 颜色编码结果 | 工具执行结果 |
| `System(text)` | 蓝色 `ℹ` 标记 + Markdown 渲染 | 系统消息 |
| `Error(text)` | 红色 `✗` 标记 + 浅红文字 | 错误消息 |

### 2.2 Markdown 渲染

Assistant 和 System 消息的内容通过 `pulldown_cmark` 解析，再由自定义渲染器转换为 Ratatui 的 `Line`/`Span`：

- **标题**：`# ` 前缀 + 深灰色，H1-H4 分级
- **代码块**：带边框的框体，支持语法高亮（Rust/Python/JS/Go/Java/C++/Bash）
- **行内代码**：浅绿色文字 + 深灰背景
- **引用**：`▍` 前缀 + 深灰色
- **列表**：无序使用 `•`，有序使用数字编号
- **表格**：Unicode 边框（┌┬┐├┼┤└┘），表头青色加粗
- **加粗/斜线/删除线**：对应 Modifier 标志

代码块高亮使用简单的词法分析器，支持关键字、字符串、数字、注释、函数调用等识别。

### 2.3 流式预览

当 Agent 正在流式响应时，`ChatArea::render_with_preview` 会在聊天历史下方额外渲染当前缓冲区的 token：

- 已确认的消息正常渲染
- 流式内容以 Assistant 消息形式追加预览
- 末尾显示闪烁光标 `▋`
- 自动滚动跟随最新内容

### 2.4 滚动

- **自动滚动**：新消息到达时自动滚动到底部
- **手动滚动**：↑/↓ 逐行，PageUp/PageDown 每页 10 行
- **滚动条**：右侧垂直滚动条，显示当前位置
- **折叠长结果**：超过 12 行的工具结果自动折叠，按 `z` 展开/收起

### 2.5 工具调用渲染

工具调用结果使用颜色编码：

- 成功结果（非错误）：黄色 `✔` + 暗灰文字
- 包含 "Error:" 或 "⛔"：红色 `✗` + 浅红文字
- 以 `[` 开头（带耗时）：绿色 `✔`

Diff 格式的编辑结果使用特殊颜色：

- `--- ` / `+++ `：青色
- `@@ `：暗灰
- `-` 开头（删除）：红色
- `+` 开头（添加）：绿色

## 3. InputArea — 输入区域

### 3.1 基本编辑

- 普通字符：插入到光标位置
- Backspace：删除光标前字符
- ←/→：光标左右移动
- Home/End：移至行首/行尾
- Ctrl+A：移至行首（Emacs 风格）
- Ctrl+E：移至行尾
- Ctrl+U：清空输入
- Enter：发送消息或执行 slash 命令

### 3.2 输入历史

- 每次发送消息后，输入内容被加入历史
- ↑/↓ 在历史中上下浏览（仅当输入以 `/` 开头时 ↑ 用于聊天滚动）
- 历史在 `clear()` 时重置

### 3.3 Slash 命令

预定义的 slash 命令：

| 命令 | 说明 |
|---|---|
| `/help` | 显示帮助信息 |
| `/clear` | 清除聊天记录 |
| `/model` | 显示当前模型 |
| `/tools` | 列出可用工具 |
| `/exit` | 退出程序 |
| `/history` | 提示使用输入历史 |

当输入以 `/` 开头时：

- 自动显示建议区域（Suggestions）
- 建议按输入前缀过滤
- ↑/↓ 在建议间导航
- Tab 或 Enter 补全选中命令
- 二次 Tab 补全第一个匹配项

颜色编码：

- 有效命令：黄色加粗
- 无效命令：红色加粗（输入后按 Enter 显示错误）

### 3.4 Tab 补全

Tab 键执行以下逻辑：

1. 如果已有 tab_suggestion，使用它并清除
2. 如果有选中建议（suggestion_cursor），使用选中项
3. 如果输入以 `/` 开头且只有一个匹配，直接补全
4. 如果有多个匹配，取公共前缀补全；如果公共前缀已超过当前输入，则建议第一个匹配

## 4. 状态栏

状态栏在屏幕底部，显示应用状态。有三种模式：

### 4.1 普通状态

```
mp_agent | 12 tools | Ready  ▾ Processing
```

- 12 tools：可用原生工具数量
- Ready / Processing：当前状态
- ▾ Processing：处理中时显示旋转 spinner（⣾⣽⣻⢿⡿⣟⣯⣷）

### 4.2 权限请求状态

```
【Permission】WRITE /path/to/file | write_file  [y]es [a]lways [n]o [d]eny [Esc]
```

- 黄色背景 + 粗体文字
- 路径截断至 60 字符
- 操作类型标签：WRITE / EXEC

### 4.3 多选择状态

```
【Choice】Pick an option (1-3) or type your custom approach below: user input...
  1. 方案 A
  2. 方案 B
  3. 方案 C
```

- 选项列表以青色显示（1-N 编号）
- 输入区域接受数字选择或自定义文本
- 按 `c` 确认自定义输入
- 按 Esc 取消

## 5. 事件处理优先级

`App::handle_key_event` 的处理优先级：

1. **多选择中** → `handle_choice_key` 处理数字/自定义输入/取消
2. **权限请求中** → 处理 y/n/a/d/Esc 决策
3. **处理中（等待 AI 响应）** → 仅 Esc（取消）和滚动键有效
4. **正常状态** → 全功能键盘输入

## 6. 渲染管线

每帧的渲染顺序：

```
App::draw(terminal)
    └── terminal.draw(|frame|
        ├── 布局计算（含建议区域条件）
        ├── ChatArea::render 或 render_with_preview
        ├── InputArea::render_suggestions（如果需要）
        ├── InputArea::render
        └── 状态栏渲染（权限/选择/普通三选一）
    )
```

帧率由主循环控制，约 60 FPS（`tokio::time::sleep(Duration::from_millis(10))`）。

## 7. 自定义扩展

### 添加新 UI 组件

1. 在 `src/ui/` 创建新模块
2. 在 `src/ui.rs` 中声明 `pub mod xxx`
3. 在 `App` 结构体中添加组件字段
4. 在 `App::new()` 中初始化
5. 在 `App::draw()` 中添加渲染逻辑
6. 在 `App::handle_key_event()` 中添加事件处理

### 修改布局

调整 `App::draw()` 中的 `constraints` 向量：

- `Constraint::Min(n)` — 最小 n 行，剩余空间给其他
- `Constraint::Length(n)` — 固定 n 行
- `Constraint::Percentage(n)` — 百分比（需 Ratatui 支持）

注意：建议区域的条件渲染会影响后续区域的索引。
